# Task 3C2A forward converter report

## Implemented surface

`app/run_adoption_schema.py` now exposes `capture_run_adoptions(db)` and `migrate_run_adoptions(db, source_metadata, *, task_metadata, run_metadata)`. Capture requires the caller-owned transaction with foreign keys off and creates transaction-local TEMP copies of current Actions, selected adoption rows, receipts, and observers before Task2B/Run3B can rebuild their owners. It validates the exact selected current Actions and Action child catalogs. Returned capture metadata contains source catalogs, selected-kind counts, receipt columns, original sequence rows, and original Action FK findings; it does not contain source bodies.

The forward converter consumes Task2B's typed Task ranges/sparse identity map and Run3B's `agent_runs` identity map, installs the declared adoption owners, replaces `action_receipts` with its assembled `execution_run_id` schema, and resolves each receipt's source execution public ID through embedded candidate progress. It preserves receipt IDs and other columns, defers provider-receipt links until all receipts exist, preserves NULL and integer-zero weak Run sentinels, and resolves positive receipt/observer Run IDs. Observer task IDs use the actual `reply_tasks` owner map. Retained Action Run refs and generic Task refs are projected through typed owner metadata; SQLite JSONB `action_data.agent_run_id` is translated while other JSON values remain semantically unchanged. Adoption identities retain the source Action physical ID, raw public key storage type, target Run, and child ID; Review child IDs remain distinct from `audit_run_id`, and predecessor references resolve to the Review child key. Selections resolve exactly once through `candidate_option()` against the immutable candidate; current source has no stored `branch_json` field. Actions are reconstructed from `task_run_entity_assembly._action_objects()`, retired adoption/attempt rows are removed, and any captured Actions sequence row is restored exactly.

The native runtime constructor and writers remain unactivated. The populated fixture uses actual old Task/Run factories and production source writers; it captures the source before either Task2B or Run3B conversion. The fixture covers two Consumers with distinct Audits, Review business ID 7 owned by Audit Run 9007, a bound nonempty option, two supplements, two receipt-level Consumer owners on one Action with no attempt map, zero and positive observer references, and a Feedback Decision public key 7 distinct from its physical ID. The canonical Run handoff remaps all four Consumer/Audit owners. It also proves catalog/target rejection and caller rollback of source rows, catalogs, sequences, and TEMP staging.
