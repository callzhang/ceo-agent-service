# Email 退订页面判断：移除无关项目文档

## 问题与验收范围

生产运行的退订页面判断只需要服务提交的主机名、页面文字和控件列表。2026-10-19 完整原生 attempt `385829` 的本轮记录中，页面任务为 1,689 字符，另有一个含 `AGENTS.md` 的 6,670 字符 User 消息；页面判断只返回一个状态与页面原话，没有调用工具。此前多个独立页面判断也出现同类项目文档输入。这份仓库操作指南不提供页面状态证据，反复进入该单用途模型上下文。

本轮只在 `email_unsubscribe_page` 的 Codex 命令设置原生 `project_doc_max_bytes=0`。完成条件是：当前 CLI 不再装配该项目文档，服务提交的页面任务与 Developer 指令不变；页面状态、证据原话、结果解析、Skill 选择、路线和浏览器执行均不退化；固定匿名案例通过；发布后核对正式服务版本与运行状态。没有自然发生的生产页面任务时，部署健康不能冒充真实页面判断回读。

## 改动前后的证据

同一工作目录、同一合成任务的 `codex debug prompt-input`：默认输入的 Developer 段为 27,672 字符、项目相关 User 段为 12,616 字符、任务段为 37 字符；加 `project_doc_max_bytes=0` 后，Developer 与任务段的内容哈希不变，项目相关 User 段为 5,742 字符，少 6,874 字符。该原生命令仍装配其他 CLI 自有内容，本改动不声称清空全部全局指令。

回归测试先对缺少路由配置与命令参数的旧实现失败，添加配置后，页面输入和空 Skill 选择保持不变。匿名只读 Codex OAuth 对照使用同一 `gpt-5.6-luna`、同一 Developer 与服务页面 prompt，分别测试带管理控件的已退订页、仍需点击的页面、含登录导航但已退订的页面，各重复两轮：原版与精简版合计 12/12 个结果均通过解析、预期状态和页面证据逐字引用；工具调用数为零。案例没有邮箱、真实退订 URL、生产页面、Work Profile、业务 MCP 或浏览器动作。

## 测试、审查与上线回读

六个受影响的定向测试文件共 177 项通过；Ruff 与 `git diff --check` 通过。代码审查仅检查本轮四处命令参数传递和页面调用点，确认默认命令不带该参数，且没有更改页面文本、结果状态或外部动作。PR、部署及正式服务回读待完成。生产真实页面结果仍需后续自然任务确认。
