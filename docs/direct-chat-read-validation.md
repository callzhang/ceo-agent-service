# Direct-chat read target: bounded acceptance

Complete saved Audit trajectories for tasks 416511, 416516 and 416558 show repeated failed freshness reads. In the latest task, three Audit attempts passed the direct conversation ID to `read_dingtalk_messages(single_chat=true)`; the tool created a conversation with no direct user identity or title, then DWS ran `contact user search --query ""` and rejected the missing query. The triggering message already carried `sender_open_dingtalk_id`. The same attempts' thread-reply calls also failed, but a direct message need not be a thread and those calls are outside this change.

Acceptance is limited to the read target: with a synthetic direct conversation and sender openDingTalkId, the native tool schema exposes the argument and the service sends exactly one DWS `chat message list-direct --open-dingtalk-id` read. With a synthetic group, it keeps the group path and result envelope. A direct call without identity or title fails locally before DWS rather than sending an empty contact query. The existing payload-sharing test suite must still pass. This does not assert that historical replies were correct, alter Audit freshness policy, change any send action, or mark a production task completed.

The first fail-first direct case rejected `direct_open_dingtalk_id` because it was absent from the tool schema. An anonymous Codex OAuth case then supplied the identity but omitted `single_chat`; the service incorrectly sent a group read. A second fail-first test reproduced that exact argument shape. The tool now selects the direct path from the stable identity alone. Release acceptance requires the fixed anonymous read cases, standard deployed commit, and health/queue/Attention/History readback. A later real private-chat Audit trace is a separate observation of natural use; until one occurs, that outcome remains unobserved rather than inferred from process health.

After the correction, the same anonymous native case again called `read_dingtalk_messages` with only `conversation_id` and `direct_open_dingtalk_id`; the fake DWS recorded `chat message list-direct --open-dingtalk-id open-synthetic-sender`, and the turn completed with a valid empty-message read.
