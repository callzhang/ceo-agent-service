# Attempt Detail 阅读与操作界面

Attempt 详情页以一次处理结果为中心：触发内容、审计说明和生成回复各只展示一次。原始 Codex 草稿不再作为第二个“回复”区块出现，避免与“生成回复”混淆。

“审计说明”已包含该 Attempt 的审计摘要；详情页不再另外渲染一个 `Audit summary` 区块，避免同一审计结论出现两次。

页面不会把底层的 `Tool uses` 技术调用单独呈现给业务用户。若审计实际读取了材料，则显示“参考资料”卡片，逐项列出材料名称、来源和与本次判断的关联；原始调用参数和输出仍仅保留在审计记录中。若 Attempt 关联了 Agent session，标题右上角提供“查看 Agent session”入口。

只有本机仍保存对应 transcript 时，Attempt 才显示“查看 Agent session”。对于已经没有 transcript 的历史 session，直接访问其旧链接会说明记录不可用，并提供关联 Attempt 的跳转；不会渲染空的 `Runtime details`。

标题左侧返回 History 使用单个箭头图标，以减少标题栏占用；其可访问名称和悬停提示仍为“返回 History”。

右侧的“需要你的判断”和“反馈迭代”属于同一条处理侧栏，使用统一卡片边界和间距。

“反馈迭代”在一张卡内分开呈现两类信息：

- 内部反馈：可编辑的“内部反馈意见”和“建议回复”。空白输入框保持单行高度，内容增加后才可向下扩展。
- 对方反馈：只读的 1–5 星评分及对方填写的反馈内容；评分由服务端的原始反馈值映射，不依据中文显示文案猜测。

即使对方尚未反馈，卡片也保留只读字段位置，避免把“尚无反馈”和“页面没有加载”混为一谈。

普通文本摘要采用按实际溢出显示的控制项：

- 内容在当前行数内完整显示时，不显示“展开详情”。
- 内容被截断时，才显示“展开详情”；展开后可“收起”。
- 容器宽度或摘要内容变化时，会重新判断是否需要该控制项。

这条规则由共享 `SummaryText` 组件执行，覆盖 Attempt、Task、Feedback、Attention 和业务详情中的文本摘要；表格行的结构化“展开详情”仍仅在它确实包含额外字段时使用。
