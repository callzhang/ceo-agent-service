# OA 有效退回轮次核验

## 目的

记录三次有效退回阈值的逐轮判定方式。阈值保持不变：只有同一项实质、可补正的缺口经过三次有效补正机会后仍未解决，第四次到达 Derek 授权节点时才可按此规则拒绝。

## 根因证据

规则本身是正确且已存在的：所选通用 OA Skill 明确规定，同一实质缺口经过三次有效退回后，第四次到 Derek 审批节点时仍由当前证据证明未解决，可以拒绝。此前把这条规则说成 Skill 中不存在，是复核者没有正确核对已加载的 Skill，属于本次分析错误；Audit 引用了真实规则，不是凭空生成了该阈值。

Attempt 15888 的 DWS 流水有四次 `REDIRECT_PROCESS`：R1 `1792379840048`、R2 `1792386090031`、R3 `1792390177943`、R4 `1792473342377`。最终于 `1792646242049` 拒绝。Consumer/Audit 的实际轨迹引用三份退回回执 15635、15645、15719（R1、R3、R4），然后把候选从退回改为拒绝；Audit 用“同一问题三次有效退回”批准拒绝，但没有说明为什么遗漏 R2，也没有比较 R2 后的补充与缺口。

独立 Consumer 按发布后的 Skill 重读完整时间线后，认定阈值未获证明。R1 后（`1792380086824`），Roy 补充了经营归属、王聪可能承担的项目管理支撑及接收安排。R2 后（`1792387371626`），Roy 进一步具体说明 ALE 工作、专家运营与辅助任务、关祥玉负责整体生产和项目管理，以及本人和原主管已协调确认交接与汇报关系，并指向原主管前序审批。依照当前 Skill，OA 中经核实的主管实质陈述本身可作为证据；不能仅因没有独立确认附件而视为未答复。该回应使职责、团队管理和交接汇报这些原缺口不再能继续累计为未解决轮次。

R3 再要求正式职责与团队构成，并引用王聪、关祥玉和两名实习生协作记录；当轮后的回复没有新增业务事实。R4 又要求发生在最新退回后的新确认，之后 Roy 表示不再补充。两条实习生消息能证明培训与协作，不能单独证明实习生属于正式团队，也不能证明他们负责整体生产或项目管理。团队人数是否存在会改变审批结论的实质矛盾仍未证明。即使将 R3 的人员范围问题单独视为新的缺口，R3 与 R4 最多构成两轮，不能与 R1 拼接成同一持续未解决的三轮阈值。

根因是 Audit/Consumer 把成功退回回执的数量当成有效补正轮次，遗漏 R2 的实质答复及其对同一缺口累计链的影响，并把“需要独立确认材料”当成必要条件。规则本身没有缺失，也不是 Audit 幻觉。现有证据不支持按“三次有效退回”拒绝；这不等于自动批准，也不推翻通常审批标准。流程已终结，本复核不修改或重放历史审批动作。

流程已经终结，本修复不修改或重放其审批结果。修复要求是拒绝候选必须带逐轮证据表，展示实际计入的三轮、每轮之后的材料和仍未解决的同一缺口；不能只给出“已三次退回”的计数结论。

## 修复要求

拒绝前逐轮生成证据表：退回与回执、当时支持缺口的可读来源、明确且可执行的补正要求、退回后的时间戳回应、回应是否补正，以及回应后仍缺少的具体事实。审批意见里的实质陈述也属于回应证据；没有新附件不等于没有回应。缺口被补正后，该缺口的累计链结束；之后的新缺口须单独判断。材料或时间线无法核实的轮次不得推定有效。
