# OA 有效退回轮次核验

## 目的

记录三次有效退回阈值的逐轮判定方式。阈值保持不变：只有同一项实质、可补正的缺口经过三次有效补正机会后仍未解决，第四次到达 Derek 授权节点时才可按此规则拒绝。

## 根因证据

规则本身是正确且已存在的：所选通用 OA Skill 明确规定，同一实质缺口经过三次有效退回后，第四次到 Derek 审批节点时仍由当前证据证明未解决，可以拒绝。此前把这条规则说成 Skill 中不存在，是复核者没有正确核对已加载的 Skill，属于本次分析错误；Audit 引用了真实规则，不是凭空生成了该阈值。

Attempt 15888 的 DWS 流水共有四次 `REDIRECT_PROCESS`，Audit 摘要称其中三次为有效退回，并以最新一次退回后没有补正材料为依据批准拒绝候选。但该 Audit 没有给出逐轮对应表，无法从其结论看出哪三轮被计入、各轮是否针对同一仍未解决的缺口，以及中间实质回应如何影响计数。流水在不同退回后确有实质回应；最后一次退回后，申请人明确表示不再补充材料。现有记录足以确认拒绝结论有可适用的规则基础，但原 Audit 的证据链不足以让人复核三次有效退回是否逐项成立。因此，已确认的问题是审核理由没有逐轮展示证据，不据此断言终态拒绝必然错误。

流程已经终结，本修复不修改或重放其审批结果。修复要求是拒绝候选必须带逐轮证据表，展示实际计入的三轮、每轮之后的材料和仍未解决的同一缺口；不能只给出“已三次退回”的计数结论。

## 修复要求

拒绝前逐轮生成证据表：退回与回执、当时支持缺口的可读来源、明确且可执行的补正要求、退回后的时间戳回应、回应是否补正，以及回应后仍缺少的具体事实。审批意见里的实质陈述也属于回应证据；没有新附件不等于没有回应。缺口被补正后，该缺口的累计链结束；之后的新缺口须单独判断。材料或时间线无法核实的轮次不得推定有效。

## 回归验证

`tests/test_oa_effective_return_rounds.py` 检查通用 OA Skill、人员 Skill 和发布清单是否保留这些规则。测试在 Skill 更新前失败（2 failed），更新后通过。原 `tests/test_oa_return_policy_skill.py` 还断言“最多退回两次”，与现行获批阈值矛盾；已改为验证“三次有效退回”且不以动作数替代逐轮核验。相关 Skill 测试 7 项通过，Consumer system release 测试 27 项通过，Ruff 与 `git diff --check` 通过。
