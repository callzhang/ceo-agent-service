# Email 阅读与模型训练

## 邮件分类

列表保留全部、待确认、已处理和退订筛选，以及页码和每页数量。打开邮件后，宽屏为列表/原文双栏；窄屏为全宽阅读。返回列表保留当前页和选中邮件。上一封/下一封只在本页已加载邮件内切换。

筛选栏右侧可搜索发件人、主题和已保存的可见正文，窄屏搜索框换行。搜索在服务端分页前进行，覆盖当前筛选范围的所有本地邮件；采用不区分大小写的字面文本包含匹配，不解释通配符或高级语法。输入停顿 300ms 后搜索，中文输入法组词期间不提交。关键词保存在 URL 的 `q` 中，变化时回到第 1 页并关闭旧详情；清空恢复列表，保留当前筛选和每页数量。搜索不扫描远端邮箱，不读取附件内容。

分类控件在正文上方。待确认邮件可以直接确认已有建议，不必先修改类别；已处理邮件也可以重新选择并保存。成功后重新读取服务端数据，失败保留当前选择。重要状态来自邮箱观察，Star 与 Flag 分开显示，并保留邮箱返回的原始信号；没有完成邮箱观察时显示未知，不显示为“未标星”。

原文只使用保存的正文，不生成摘要，不执行邮件 HTML、脚本或远程资源。历史已平铺或截断的内容不能恢复成原邮件排版。引用与附件元数据单独展示，不读取附件内容。

退订记录列表的状态列直接显示每封邮件最新一次退订的结果（退订成功、该来源已退订、本次未完成退订、退订执行失败、正在退订等，成功绿色、失败红色），取值与详情的处理记录一致，不再显示分类的“已处理”。未完成的退订在状态下方用小字写明原因（未找到可操作的退订入口 / 退订需要登录验证），措辞与详情相同。邮件详情是一页从上到下全部展开的内容，没有折叠区也没有标签页：分类确认、处理记录、原文（含引用与附件）、分类依据、技术详情依次排开，处理记录在原文之前，候选分布这类长内容放在后面。

处理记录按动作展示结果、时间及关联 Attempt。退订任务结束不代表退订成功：界面使用回执 outcome，缺结果时显示未知。退订链接直接显示在退订记录里（打开详情时通过独立读取接口取回，可复制）；记录里没有保存地址时明说“没有保存退订地址”，不阻止查看 Attempt。完整日志、回执标识和 ActionPlan 在页面底部的技术详情中。

## 模型训练

总览显示当前影子/主模式、真实候选的分数与延迟。历史 registry 的 active 登记不代表当前线上模型。晋升仍由服务端门槛控制，切换保留确认和版本冲突保护。

“新建训练”选择来源、类别和模型家族。样本预览按与训练相同的冻结文件夹快照筛选规则，对邮件身份去重；不创建训练任务或写入反馈。计数包括训练与验证数据，不等于每个模型最终拟合的行数，也不保证全部模型都满足训练条件。提交时重新校验快照和各模型条件。

有效选择没有匹配样本时显示 0 并禁止提交；读取错误则显示错误和重试。改变选择会取消旧预览。提交期间锁定选择，防止显示内容与提交内容不一致。任务提交不等于训练完成，界面不构造百分比或成功状态。

“晋升设置”单独编辑门槛；版本详情分为效果、数据与参数、技术信息，保留完整模型名和评测证据。趋势按模型家族成线；同一模型家族的版本即使被其他家族的训练记录穿插，也会保持连续。评测数据、协议或类别集合不同会在鼠标提示和趋势文字数据中明确标出，不能据此推断可比较的能力提升；没有测量不画作零分。

候选摘要优先显示候选版本保存的训练样本数。Embedding + MLP 尚未保存端到端延迟时，显示输出头 P95，并明确标注“输出头实际测量；端到端未测量”；不会把该值伪装成完整邮件分类的端到端延迟。

## 本次尚未补齐的能力

- 重要标记目前只读。现有外部动作路径支持设置，但没有完整的取消标记与 UI 回读接口；本次没有新增绕过 Audit 的直接邮箱写入。
- 总览不把重叠来源的记录数相加充当全局可训练数。精确去重计数在具体训练选择的预览中查看。
- 训练进度只显示现有接口实际提供的状态和运行标识；缺少持久化的逐模型阶段时不推断成功或失败。

这些是当前实现差距，不是对已批准设计的重新定义。发布前需明确接纳差距或继续补齐。
