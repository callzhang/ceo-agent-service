## Reachable import caller and source-specific identities

The CLI calls `apply_task_semantic_import_manifest` ([CLI](../app/cli.py:5236)). Its plan uses Business public IDs for WorkProjects and WorkTodos, and the WorkUpdate projection's public ID for WorkUpdates ([plan](../app/task_semantic_import.py:255)). The present planner hardcodes every WorkProject `matched=False` and every WorkUpdate `disposition='history_only'`; only a source-backed WorkTodo can currently become `formal_task` ([project/todo/update cases](../app/task_semantic_import.py:274)). The manifest checksum, full corpus fingerprint, source row digest, supporting source digests, and classification are checked before or within the import transaction ([validation](../app/task_semantic_import.py:390), [apply](../app/task_semantic_import.py:497)). The apply loop looks for an existing link by the unique source column and verifies the target and evidence before treating a retry as skipped. History-only items create no link. The successful current path creates a formal Task and inserts `(task_id, work_todo_id)` in one `business_task_transaction`; the official-Project `(project_id, work_project_id)` branch is present but is not emitted by the current planner. The return contract contains created, skipped, formal-task, official-project-match, and history-only counts, with no link ID ([insert/return](../app/task_semantic_import.py:529)).

The lookup happens **before** the history-only branch and binds `item.legacy_row_id` to whichever source column `_link_column` selects ([lookup](../app/task_semantic_import.py:515)). For WorkUpdates that value is public ID, although a selected-source LegacyLinks WorkUpdate row stores a physical Action ID. Current planning creates no WorkUpdate link, but an existing row with coincident numeric IDs could be looked up as a history-only item and rejected as conflicting. The next caller unit must explicitly resolve this source-specific lookup identity; the present source capsule does not infer a replacement rule or waive existing rows. A repository-wide `app/` search found no other runtime SQL reader/writer of LegacyLinks beyond the import and schema/migration/guard paths; tests directly seed the other five target alternatives.
