# History 可处理状态

History 对审批、回复、会议和任务使用同一套管理者关注状态展示。业务判断由 Agent 和结构化结果负责，
页面不根据消息正文猜测原因或操作。服务不维护 `unknown`、`reconciled` 或 `side_effect_state` 状态机；
这些字段在旧数据中出现时只作为历史事实展示，新执行不得写入。

## 需要管理者处理

卡片和详情页固定显示：

- 原因：读取已持久化的审核摘要、执行错误或任务结果。
- 外部动作标识（如有）：`operation`、`target` 和 provider 稳定 result identifier，仅用于关联和去重。
- 选项：Agent 提供的业务选项，以及当前状态允许的重试、暂不处理、人工处理和技术详情。

在 History 选择业务选项或“暂不处理”时，Web 请求只记录明确指令并重新排队同一个 `reply_task`。原 attempt
的选择状态与任务重排队在同一数据库事务内完成；重复提交同一选项复用同一个 attempt 和执行代次。

审批类“暂不处理”会把以下要求交给 Agent 执行：通知实际申请人审批仍待处理、缺少的材料或事实，以及申请人
下一步需要做什么。Web 页面本身不直接发送通知或执行审批。

## 自动恢复

失败任务按统一重试规则处理：Agent 下一次 turn 通过当前业务 Skill 读取必要事实，再决定继续、修正或终止。
页面直接读取 `available_at`，显示当前尝试次数、最大次数和下一次自动重试时间，不在渲染时重新计算。重试
耗尽进入 `failed`，并展示实际错误和下一步；不产生 reconciliation 或未知结果按钮。

## 审批状态归并

History 以 OA `process_instance_id` 作为审批事项身份，不以单次 Attempt 作为审批最终状态。`task_id` 只表示流程中
的一个审批节点，不参与拆分审批事项。

- Agent 重试和启动前失败都从原始 `reply_task.oa_url` 继承 OA 流程与任务标识。
- 同一审批事项只在 History 首页展示一条当前记录，固定选择 `(created_at DESC, id DESC)` 的最新 Attempt；筛选、计数、
  分页、卡片编号、详情链接、当前系统状态、注意力和恢复入口都以这条记录为准。旧记录保留在审批详情时间线中。
- 业务结果与当前系统状态分开显示。业务结果批量读取当前页所有审批流程的全部 Attempts，并按 Attempt 从新到旧查找
  持久化强证据；已确认的同意、拒绝或实际退回优先于留言，只有没有终态动作时才保留最新已确认留言。
- structured 审批动作只信任 `payload.argv` 解析出的 DWS canonical command、流程标识和需要时的任务标识。退回还必须是
  允许的 `revert-task --action`；普通成功回执不能把“退回”猜成已退回。
- 这些归并规则只使用现有持久化字段和批量只读查询，不新增审批 case 表或数据库迁移。

## Agent 与服务边界

- Service 不审核命令名称、MCP 工具、Skill、读写模式或“未知工具”，也不要求纯读取 receipt。
- Agent 在重试前按当前 Skill 读取目标状态；若 provider 已返回稳定 result identifier，则沿用同一 `operation` 和
  `target` 做去重。
- 会议和任务子系统没有安全重跑入口时，History 不生成新的重放接口，只链接人工处理和技术详情。
- 终态记录不显示管理者操作按钮；失败记录仅显示当前失败原因和可用的重试/反馈入口。
