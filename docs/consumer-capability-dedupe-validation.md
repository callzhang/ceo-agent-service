# Consumer 能力说明去重：有限验收（2026-10-19）

本轮只检查 `app/consumer_agent.py` 的 `AGENT_CAPABILITY_INSTRUCTIONS`。生产原生 Consumer Developer 输入中，这一段约 3,887 字符，并在不同任务中全量出现；相邻的能力目录已提供 `read_system_action_contract` 精确查询入口。保存的 Developer 模板与仓库种子字节一致，其中“原请求与取证”已说明按需取证、普通文档工作、受控动作边界、失败和回执。角色合同与决策证据段还覆盖候选、Audit、事实缺口和人工决策。重复说明不是新的工具能力。

预期：删去可由上述共同段落承担的复述，让此段只解释服务角色真正需要的工具使用细节。实际：当前段落还重复描述“先读来源”“普通写入不自动变成受控动作”“summary 不是回执”“仅系统执行受控动作”“技术失败不伪装成业务提问”等原则。两处不能直接逐字比较，因为模板用中文、能力段用英文；逐项按语义和对应源码核对。此项不更改保存的 Developer 模板、Work Profile、能力目录、Skill、结果 schema、路由和会话绑定。

## 完成条件

1. 精简后的 Consumer Developer 输入实测减少至少 1,000 字符；`AGENT_CAPABILITY_INSTRUCTIONS` 以外的装配段落及完整 Task 事实、Pydantic 校验逐字不变。Settings 当前预览通过同一装配路径显示新内容；历史预览仍读取保存的旧输入。
2. 保留实际能力边界：Consumer 普通文档/工件工作可做并须有读回；受控动作仍只由 System 执行；钉钉业务读取使用声明的 `mcp__agent_cli` 工具，不通过 shell 调 `dws`；目标使用稳定身份；仅真实依赖读取失败使用 `dependency_read_unavailable`，无匹配或事实不全不能冒充停机；风险拒绝不自动改道重发。受众、OA、人工决策和结果字段规则不退化。
3. 先运行会失败的装配回归，再跑受影响的本地测试。用相同模型、事实、工具假返回及完整结果校验，分别比较旧/新输入的匿名定时文档、普通聊天来源读取失败、普通聊天无匹配、OA 精确实例、敏感群受众和一次同 session 续会话；只读，不连生产业务 MCP、不执行外部动作。检查实际工具调用、业务判断、完整结构化结果，不能只凭进程退出判定通过。
4. 通过独立审查并记录输入差异、模型结果和风险后，按仓库流程合并、部署、回读 PID、healthz、队列、Attention、History、Settings 当前及历史输入。没有自然业务样本时，只报告上线与固定案例，不声称真实业务效果。

如果固定案例未达到行为不退化，本轮判为 no-go，不为通过测试而增加场景特例或 fallback。
