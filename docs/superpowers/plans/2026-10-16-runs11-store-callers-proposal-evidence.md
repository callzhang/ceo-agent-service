# Runs11 Store caller proposal (unselected)

The companion patch changes only `app/store.py` and the sole production metadata writer in `app/meeting_alignment.py`. It is based on the installed c14cb181d Runs11 foundation. It was tested on a copied `app` tree and disposable SQLite databases; no application or test file in the worktree was edited.

The Store metadata upsert now reads the source-shaped Runs11 projection and inserts with `insert_run11_fact`. On an existing session, it changes source type, source ID, title and `updated_at` on the metadata record. It preserves public ID, session identity and `created_at`, and creates no persistent FTS entry. Two metadata sessions may retain the same source ID. Search reads only those metadata members through `run11_projection` and orders `updated_at desc,id asc`; every native-file, RAM FTS/vector cache, scoring and result operation after that read remains unchanged. The meeting writer no longer passes its unused `embedding_client` argument.

The setup writer uses the same helper for the seven supplied source fields and passes its preexisting `case when ? = 'running' then '' else current_timestamp end` expression for `finished_at`. The helper supplies `started_at` through the source default mapped to `created_at`. The public method returns the helper's native public `lastrowid`; the list reader uses the source-shaped projection with the original step/action filters, limit and ID-descending order. Arbitrary status, evidence and output strings remain accepted.

The companion test script initialized a real current54 `AutoReplyStore`, installed Email's exact fresh source declaration (Email owns it), captured mapped Runs8, and called `migrate_run11_schema` in the same FK-off transaction. It then exercised the same Store object without invoking a second constructor. On the original Store methods, four tests failed at missing retired tables after the pure migration. Against the proposed copied application, all four passed in 7.05 seconds: alias/upsert/title search; exact two-row native tie `[1,2]`, raw target `[2,1]`, public search `[1,2]`; setup fields, filters, arbitrary values and rollback; and native fresh setup CASE equivalence. Copied-code compile and repository-configured Ruff passed. `git apply --check`, apply/reverse checks, and byte comparison of the replayed patch passed. Exact patch/test SHA256 and AST scope are in the companion JSON.

The current constructor, Email sample callers, current declaration recognition, and paired coordinator still select 54 tables. Existing direct physical test fixtures need the separate root/test-owner conversion before selection. This proposal proves the four scoped Store methods and sole meeting call on an isolated Runs11 database; it does not establish cold 51-table constructor behavior, actual-source copy, native CLI, provider, UI, production or final 11-table acceptance.
