# Unselected Workbench Tasks8 caller proposal

This is a complete, bounded `app/workbench/store.py` proposal, **not an applied caller conversion or runtime acceptance**. The patch changes two native inserts, twelve native updates, three direct status/sequence readers, and the timeline projection's source qualifier. It preserves all 79 function signatures/return annotations/decorators; 16 function bodies change and the other 63 are AST-identical. No application/test file, historical factory, constructor, source-body policy, database, native CLI, provider, service or production state was changed in this work. Root owns paired behavioral proof and the complete integration plan before application transfer.

Module-local `WORKBENCH_TASK_SQL`/`WORKBENCH_TURN_SQL` now come from `task20_projection`. Historical `task_storage` projection factories/defaults stay byte-identical. Imports of `task_physical_id` and `task_id_expression` remain: their Workbench use is limited to the two original text-ID kinds and physical identity/parent mapping. Retained child projection declarations at92,96,106 remain unchanged. Module-level recovery SQL constants and `_TURN_TRANSITIONS` remain AST-identical.

Each SET uses `task8_set_parts(kind, {}, update_sql={...})`. All Workbench update fields are payload fields, so there is no structural SET or helper-bound value in this file. Each original execute tuple remains AST-identical and binds the same native scalar placeholders in the same order. The builder emits empty `.parameters` for these calls; consuming it would add nothing. CASE references are explicit `task20_column` expressions; SQL receives native scalars and the builder owns exact scalar encoding. Inserts use the builder's `.parameters` because they supply bound values, including `legacy_key`/`parent_id`. There is no new transaction wrapper, cursor adapter, business field, parser, branch, policy, fallback or exception translation. Workbench has no UPDATE FROM, leading CTE, UPSERT or RETURNING site; none is invented.

## Observed validation

Validation ran only on the patch/candidate in a task-owned `/tmp` directory, with no imports that open a database and no database or method execution. AST checks passed for all79 signatures/return annotations/decorators, all63 nonselected function bodies, all pre-existing module assignments, twelve original UPDATE execute parameter tuples, all ten rowcount comparisons after masking only changed SQL arguments, and all24 transaction-control execute calls. Constructor and `_connect` bodies are unchanged; the proposal does not import or call codec registration. All twelve SET calls pass an empty bound-value dictionary and only `update_sql`. Source SHA was rechecked after validation. The exact owned temporary directory was removed and its absence verified. A temporary validation-script bug passed `None` to `ast.dump` for unannotated return types; correcting that validator allowed the complete signature check to run. The proposal itself was unchanged by that correction.

These checks establish patch integrity and bounded static preservation. They do not establish SQL execution equivalence, public-method behavior, migration, sequence/constraint equivalence, filesystem recovery or runtime activation. The accepted component601 cases are separate component evidence, not tests of these caller methods.

### Integration dependency outside this bounded patch

`app/workbench/native_events.py:30` imports the historical `WORKBENCH_TURN_SQL`; `terminal_cached_turn_ids` uses it at99 and `hydrate_events` at173. A nonempty live cache makes `WorkbenchStore._connect` traverse the former after a write; agent event hydration traverses the latter. This proposal intentionally does not edit that file. Full integration must select its typed projection too, preserving its native source/body behavior, and exercise both paths with a nonempty cache and agent events. Empty-cache/control-only fixtures would conceal this unresolved caller dependency. Store and Email `_open_connection` must both register the exact scalar codec during complete cutover; Workbench inherits Store's connection. No constructor/registration change belongs in this patch.

Root's remaining acceptance also includes all other20-kind callers, complete migration/copy/current-fact inverse, genuine predecessor writes and reforward, native CLI fake-outbound/UI/business-result/receipt proof, final11-table reconciliation and publication. None is claimed here.
