# Email 统一分类、训练与 API Agent 设计

## 目标

将 Email 页面收敛为统一的邮件处理入口：已处理与待反馈使用同一套列表和详情交互，已处理邮件可以重新分类并立即执行新类别动作。模型训练页支持多模型、多来源数据和手动训练；Agent 直接通过 Codex API 调用，不创建 Codex CLI task。

## 范围与边界

- 业务类别：外部账单、融资、人事、法务、通知、个人、购物、工作。
- `important` 是独立关注标签，不是业务类别；可由 Star / Flag 等邮箱信号形成。
- `junk` 是内部分类结果，固定映射到每个邮箱账号的系统 Trash，不创建可配置业务文件夹。
- 无法确定类别的邮件显示未分类并留在 Inbox。
- 邮件正文不生成摘要；列表显示原文前段，详情显示完整正文和引用内容。
- 附件只读取并展示 metadata，不读取附件内容。
- 本设计不增加邮件回复行为；明确要求处理时才创建 Email task。

## 统一邮件页面

页面提供三个视图筛选，而不是两套独立页面：

- 全部：所有已进入 Email Service 处理范围的邮件。
- 待确认：尚未得到最终分类的邮件，显示 Agent 或模型建议及置信度。
- 已处理：已有最终分类并完成当前动作的邮件。

列表与详情使用同一套组件。列表直接显示发件人、主题、原文前段、分类、置信度、重要标签、处理状态和时间；不调用摘要模型。详情 drawer 显示完整正文、引用、收件人、附件 metadata、分类证据、模型版本和动作证据。

### 重新分类

已处理或待确认邮件均可在详情中选择类别。保存后：

1. 写入最终分类及来源（用户、Agent 或模型）。
2. 立即执行新类别的固定动作。
3. 按新类别同步邮件文件夹、Star / Flag 和系统 Trash 状态。
4. 记录动作结果和失败原因；失败不伪装为成功。

未选择类别的邮件不执行移动动作，继续留在 Inbox。

## 分类与 Agent 调用

日常分类优先使用本地或 GPU 服务模型：

- TF-IDF + Logistic Regression；
- fastText；
- Embedding + MLP。

模型可以多选。一次训练任务对每个选中模型分别训练、评估并生成候选版本，不合并模型权重。成熟模型由用户通过 enable toggle 切换为主模型，不自动晋升。

Codex Agent 不通过 CLI 或本地 task 执行，Email Service 直接调用 Codex API。API 只接收主题、发件人、收件人、正文、引用正文、附件 metadata 和当前类别描述，并要求严格结构化 JSON 返回。API Agent 用于：

- 冷启动人工标注；
- 本地模型低置信度 fallback；
- 根据用户反馈优化类别描述；
- 退订网页多步流程。

API client 必须有超时、有限重试、并发限制、响应 schema 校验、token 成本记录和失败降级。API Agent 不生成邮件摘要。

## 模型训练页面

训练页展示当前运行模式：Agent 主分类、影子模型或模型主分类，并显示当前主模型、候选模型和晋升门槛。

训练表单支持：

- 多选 TF-IDF、fastText、Embedding + MLP；
- 默认勾选全部可用训练数据；
- 按数据来源取消选择；
- 按类别取消选择；
- 手动开始训练；
- 查看排队、运行中、成功和失败状态。

默认训练来源包括：用户确认标签、Agent 自动标签、邮箱文件夹标签、Star / Flag 形成的 important 标签、Trash 形成的 junk 标签。每条训练记录保留来源、标签版本、邮件 ID、模型版本和数据集摘要，实验数据不反写用户反馈。

每个模型版本显示：训练开始与完成时间、样本总数、各类别样本数、数据来源、训练参数、评测指标、端到端延迟、artifact digest 和状态。历史版本可比较并展示趋势图。

## 邮箱文件夹与分类同步

文件夹是用户邮件分类事实来源。结构同步只采用单向方向：

```text
CEO Email Service → Mail Server
```

用户在 Email Service 创建或修改业务类别时，服务为每个启用账号创建或验证对应文件夹；分类动作把邮件移动到绑定文件夹。服务不把服务器新建文件夹反向创建成业务类别。服务器中的已有文件夹和邮件位置可以作为训练标签来源，但不改变类别配置。

`junk` 始终使用账号的系统 Trash；`important` 不占用业务文件夹，通过 provider-aware Star / Flag 适配器处理，不假设所有邮箱的 flag ID 相同。

## 数据与错误处理

- 服务器返回 `category=null` 时，API 和 UI 都显示“未分类（留在收件箱）”，禁止渲染为空白。
- 缺少正文时明确显示缺失状态，不使用列表 preview 冒充正文。
- 模型或 API Agent 返回非法 JSON、未知类别或超时，记录失败并进入待确认，不执行分类移动。
- 邮箱动作失败时保留最终分类与动作失败证据，允许重试，不显示为已完成。
- API 调用和训练任务不得创建 Codex CLI task。

## 验证

- 前端测试覆盖统一筛选、已处理重新分类、未分类 Inbox fallback、候选分布、正文与附件 metadata 展示。
- API client 测试覆盖结构化响应校验、超时、重试、非法类别和成本记录。
- 训练测试覆盖多模型选择、数据来源筛选、版本生成、指标保存、模型保存重载和候选模型晋升边界。
- 集成验证覆盖重新分类后的文件夹和 Star / Flag / Trash 动作，以及动作失败证据。
- 浏览器视觉验证覆盖列表、drawer、候选分布、分类操作栏和模型训练页。

## 非目标

- 不生成邮件摘要。
- 不通过 Codex CLI 创建 Agent task。
- 不把 Agent 自动标签直接视为用户确认；其来源必须单独记录，并可在训练页选择是否使用。
- 不自动将候选模型切为主模型。
- 不实现邮件回复。
