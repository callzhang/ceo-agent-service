# 顶部导航栏服务更新交互方案（用户已确认）

目标：发现 GitHub 上游的新代码，先展示本次更新内容，由用户确认后暂停新任务领取，等当前执行任务完成，再更新、重启并验证服务。

**入口与检查**

沿用已配置 Git remote/branch 的检查机制，默认 origin/main；后台默认每5分钟检查一次。导航栏每60秒读取检查结果。有新提交时，导航栏右侧显示「更新服务 · 提交数量」。没有更新时隐藏更新按钮；检查失败单独显示检查失败及重试入口，不能误报已是最新版本。

**弹窗**

点击更新按钮只打开弹窗，不开始部署。弹窗显示当前版本、目标版本、提交数量和更新说明。打开时重新核对上游版本，说明与目标提交绑定。

只有1个提交：直接显示提交标题和正文。多个提交：把当前生产版本到目标版本之间全部未部署提交的标题、正文交给现有AI运行能力，总结成500字以内中文更新说明；不沿用现有仅20条标题的限制。说明覆盖主要功能、修复和用户可感知的变化，不虚构提交未说明的效果。同一版本复用已生成说明。完整提交列表可展开查看。AI生成失败时明确展示失败、重试入口和原始提交列表，不伪装成已生成总结。

弹窗固定说明：「更新期间暂停领取新任务，当前任务继续完成；新消息、Queued和延迟retry会保留，服务恢复后继续。」底部为「取消」「确认更新」。

**执行与反馈**

确认后通过正式部署入口安装弹窗展示的目标版本。沿用现有发布互斥锁、暂停领取、在途计数、备份、构建、重启、健康检查和回滚机制；不使用跳过排空的选项。

导航栏显示准备更新/等待当前任务结束/等待服务恢复等与实际状态对应的进度，更新中不能重复点击。等待期间状态读取不等待发布互斥锁，页面仍可查看队列。连接中断时明确显示重新连接，不仅凭网络断开宣称重启成功。

服务恢复后核对实际安装版本与部署回执，确认成功再自动刷新页面。失败、超时或回滚时显示实际原因，恢复任务领取；不丢弃待处理任务，不改retry时序。

**实现与验证范围**

复用已有Git上游检查与正式app.deploy入口，将React GlobalNav接入更新按钮、说明弹窗与进度反馈。增加全部commit读取、500字以内AI摘要及按版本复用；将后台检查默认间隔由现有6小时改为5分钟。旧网页升级入口的独立更新器与正式生产检出保护流程需要在本次接入时统一到正式部署路径。

验证：无更新/有更新/检查失败；单个及多个提交且超过20条仍完整覆盖；摘要长度与失败重试；确认前不部署；确认后只安装弹窗目标；重复点击；排空与超时恢复；服务断连、恢复、成功和失败反馈；桌面与窄屏导航显示。最后通过正常发布流程上线，读回版本、PID、healthz、队列、Attention和History。
