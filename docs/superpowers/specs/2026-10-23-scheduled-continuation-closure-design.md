# 通用定时任务续跑闭环核查

日期：2026-10-23（America/Los_Angeles）。状态：用户已批准；按执行计划直接开展只读核查。

## 目标与范围

确认现有通用定时任务机制在失败重试、Audit 退回修订时，能否保留有效成果、继续推进，并以真实证据结束。OKR 报告是核查案例，结论落在共用执行机制；不为某一种报告追加规则。

本轮只读核查。复用保存的实际输入、完整原生 trajectory、运行关系、产物与外部回执，以及已通过的测试/评测。不修改代码、prompt、Skill、审核或重试策略，不创建或重放定时任务，不进行模型调用或外部写入。Codex harness 的自动压缩不属于本项。

## 核查动作

1. 记录核查时生产提交，以及每个样本实际使用的任务定义、Skill/配置版本、运行路线、执行代次和原生轨迹范围；历史输入不以当前配置重建。
2. 按真实先后顺序读取每个固定样本的完整调用范围，连同准备阶段、工具调用与返回、最终结果、Audit 反馈和执行回执。源文件缺失或范围不完整直接记录缺口。
3. 对齐“前一轮已完成什么、下一轮实际收到什么、下一轮使用了什么”。区分必要复核与无效重读；不同字段、变化来源、先前截断/读取失败不能只因请求相似就算重复。
4. 对照现有共用执行代码与修复版本，判断问题仍存在、已修复，还是只缺生产证据。相关代码或输入未变化且已有充分有效证据的检查不重跑。

## 验收条件

| 条件 | 所需证据 |
| --- | --- |
| 身份与版本连续 | 同一调度发生次、任务和执行代次的关系明确；session、配置、来源或产物变化可追溯，不把新任务的成功算成旧任务恢复。 |
| 有效成果得到保留和使用 | 已保存的来源、分析或报告产物能在后续输入/工具返回中准确取得；后续步骤沿未完成工作推进。若重新读取或重算，能从完整轨迹解释必要性。 |
| 反馈真正进入修订 | 后续 Consumer 收到对应候选及 Audit 意见，生成新的修订；相关来源和必要业务行为保持正确，旧运行与反馈可追溯。 |
| 终态与实际结果一致 | `done` 的报告具有所需 Audit 结论、文档内容读回及发送动作的服务回执；不依赖 Agent 自述。未完成的运行按现有边界停止并保留原因，不把已发生外部动作重新执行。需要补证时只读查询同一结果。 |
| 通用性与开销可说明 | 明确指出共用代码路径及已有跨报告证据；不足时只报告已验证的范围。列出可获得的逐轮耗时、输入长度/token、来源读取及已完成产物，缺失指标标为未记录，不据字符数推断生产提速。 |

## 交付与终点

交付一页核查结论：逐项列“预期、实际、证据定位、结论”，保留运行/回执引用，不复制业务正文、凭据或整份日志。

- **已闭环：**上述条件在明确范围内均有证据支持，记录无需修改，结束本项；不为证明优化而继续增加测试或改动。
- **未闭环：**完整轨迹证明仍有机制问题，列出一个确认的原因、受影响的共用边界和最小修复建议。本核查在问题定位处结束；实现属于后续单独计划。
- **证据不足：**列出确切缺失的轨迹、版本、产物或回执，以及能补齐它的最小只读动作；不能写成已闭环或已确认代码缺陷。本轮不通过新执行制造证据，不无期限轮询。

本项不负责 Task 输入改造、Meeting 审核、所有报告的业务规则验收或全局性能优化。spec 经用户审阅后再写核查执行计划。
