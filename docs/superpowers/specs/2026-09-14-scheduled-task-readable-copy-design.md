# 定时任务可读名称与描述设计

## 背景

当前定时任务名称大量使用“检查”“扫描”“恢复”，描述又使用“写入 reply task”“统一 Dispatcher 消费”“创建后续处理任务”等内部实现语言。用户从任务列表看不出发现内容后系统会做什么，也容易混淆“检查 DingTalk 消息”和“检查 DingTalk 会议”的业务边界。

## 目标

- 名称直接表达任务最终完成的业务动作。
- 描述说明检查范围，以及发现真实输入后系统如何处理。
- Cron 频率继续由现有自然语言计划单独展示，名称不重复频率。
- 普通界面不展示队列、Dispatcher、Consumer 等内部机制。
- 不改变 Cron、时区、服务命令、Agent Prompt、Skill、启停状态或历史运行记录。
- 更新仓库默认文案和当前仍使用旧默认文案的内置任务，同时保留用户自行编辑的名称与描述。

## 方案选择

### 采用：业务结果型文案

名称使用“动作 + 对象”，描述使用“读取范围 + 发现后的业务处理”。这样即使用户修改 Cron，名称仍然准确。

### 未采用：技术阶段型文案

“钉钉消息 Trigger”“会议 Consumer”能帮助开发者定位流程，但普通用户仍需理解内部架构。

### 未采用：频率型文案

“每分钟处理钉钉消息”初看直接，但频率已经由计划预览展示，而且用户修改 Cron 后名称会失真。

## 最终文案

| 内置任务 | 新名称 | 新描述 |
| --- | --- | --- |
| DingTalk 消息 | 处理新的钉钉消息 | 发现新的单聊、群聊 @ 消息或会议邀请后，由 Agent 判断是否需要关注、回复或处理日程。 |
| DingTalk 会议 | 整理已结束的钉钉会议 | 发现已经结束且会议资料可用的钉钉会议后，由 Agent 整理会议内容和后续事项。 |
| 微信消息 | 处理新的微信消息 | 发现已配置联系人或群聊的新消息后，由 Agent 按授权范围判断并回复。 |
| DingTalk OA | 处理待审批的钉钉 OA | 发现新的待审批事项后，由 Agent 按审批规则处理，并把结果通知实际申请人。 |
| 工作来源 | 同步工作事项 | 从日历、待办和工作目录收集最新变化，由 Agent 更新已有工作记录或创建有明确证据的新任务。 |
| OKR 周报 | 生成并发送每周 OKR 周报 | 读取管理者最新 OKR，生成本周管理进度周报并发送。 |
| AI 听记 | 同步钉钉 AI 听记到工作区 | 把新增的听记摘要和逐字稿同步到工作区，并保存同步进度。 |
| DingTalk 消息补查 | 补查遗漏的钉钉消息 | 扩大消息读取范围，补回常规检查可能漏掉的单聊、@ 消息和更新后的会议邀请，发现后交给同一套 Agent 规则处理。 |

“执行任务”下拉菜单同步使用可读动作名称：读取新钉钉消息、读取新微信消息、读取已结束会议、读取待审批 OA、收集工作来源、同步听记到工作区、生成并发送 OKR 周报、补查近期钉钉消息。下拉菜单说明只描述该固定代码实际读取或生成的内容，不出现 reply task、Dispatcher 或 Consumer。

## 数据与代码边界

仓库默认名称和描述由定时任务种子定义，服务命令目录只定义“执行任务”下拉菜单的名称和说明。两者语义保持一致，但任务名称和服务命令名称承担不同用途，不互相动态生成。

服务启动时按 `migration_key` 找到内置任务，并分别判断名称和描述：

- 当前字段仍等于任何一个仓库旧默认值时，升级为新默认值。
- 当前字段不等于仓库旧默认值时，视为用户编辑，原样保留。
- 名称和描述独立判断；用户只改过其中一个字段时，只保留那个字段。
- 已删除任务不恢复，也不修改。
- 不新增数据库字段，不重写历史运行快照。

## 页面行为

任务列表继续保持现有结构：名称、运行状态、业务描述、自然语言计划、下次运行、最近状态。只替换不清晰的名称和描述，不增加新的卡片字段，也不改变布局。

任务编辑区继续允许用户修改名称和描述。服务命令的技术标识仅保留在“技术详情”中，不作为默认可见文案。

## 错误与兼容行为

- 无法识别为仓库旧默认文案的任务不自动修改。
- 用户自建任务不参与内置文案升级。
- 旧运行记录继续显示运行当时保存的名称和描述，保证历史证据不被改写。
- 文案升级不改变版本冲突、启停、手动运行和删除语义。

## 测试与验收

1. 先增加会失败的种子测试，验证八个新名称和新描述。
2. 增加升级测试：旧默认文案会升级；用户自定义名称和描述分别保留；已删除任务不变。
3. 增加服务命令目录测试，确认下拉菜单名称清楚且默认说明不含内部实现词。
4. 更新前端测试，确认列表和编辑器展示新文案，运行记录仍只在技术详情中显示命令标识。
5. 运行 Python 聚焦测试、前端页面测试、前端构建和全量 Python 测试。
6. 重启 `com.ceo-agent-service.main` 后回读数据库和浏览器页面，确认八个内置任务显示新文案、服务健康、队列可恢复且没有新增失败或卡住任务。

## 非目标

- 不修改定时任务布局、配色或响应式行为。
- 不修改 Cron 表达式或自然语言解析。
- 不改变 Trigger、Agent、Skill、Runtime 或队列架构。
- 不批量改写用户自建任务。
