# 定时任务可读名称与描述设计

## 背景

当前定时任务名称大量使用“检查”“扫描”“恢复”，描述又使用“写入 reply task”“统一 Dispatcher 消费”“创建后续处理任务”等内部实现语言。用户从任务列表看不出发现内容后系统会做什么，也容易混淆“检查 DingTalk 消息”和“检查 DingTalk 会议”的业务边界。

## 目标

- 名称直接表达任务最终完成的业务动作。
- 描述说明检查范围，以及发现真实输入后系统如何处理。
- Cron 频率继续由现有自然语言计划单独展示，名称不重复频率。
- 普通界面不展示队列、Dispatcher、Consumer 等内部机制。
- 除新增独立的日历邀请任务及拆分其 Consumer Prompt/Skills 外，不改变现有 Cron、时区、启停状态或历史运行记录。
- 更新仓库默认文案和当前仍使用旧默认文案的内置任务，同时保留用户自行编辑的名称与描述。

## 方案选择

### 采用：业务结果型文案

名称使用“动作 + 对象”，描述使用“读取范围 + 发现后的业务处理”。这样即使用户修改 Cron，名称仍然准确。

### 未采用：技术阶段型文案

“钉钉消息 Trigger”“会议 Consumer”能帮助开发者定位流程，但普通用户仍需理解内部架构。

### 未采用：频率型文案

“每分钟处理钉钉消息”初看直接，但频率已经由计划预览展示，而且用户修改 Cron 后名称会失真。

## 最终文案

| 内置任务 | 新名称 | 新描述 |
| --- | --- | --- |
| DingTalk 消息 | 处理新的钉钉消息 | 发现新的单聊或群聊 @ 消息后，由 Agent 读取最新上下文，决定回复、表态、澄清或不处理。 |
| DingTalk 日历邀请 | 处理新的钉钉日历邀请 | 发现新的会议邀请后，由 Agent 读取最新邀请和日程冲突，决定接受、暂定、拒绝或向邀请人澄清；执行后核验日历状态。 |
| DingTalk 会议 | 同步会议结论与管理者视角 | 会议结束且听记可用后，由 Agent 总结关键结论、分歧和行动项，确保管理者观点被准确传达；发现未对齐时发送会后澄清。 |
| 微信消息 | 处理已授权会话的新微信消息 | 发现已启用的好友新消息或群聊 @ 后，由 Agent 判断是否回复；仅按已配置范围和发送模式处理，不读取或回复其他会话。 |
| DingTalk OA | 处理新的钉钉 OA 审批 | 发现新的或有新处理记录的待审批 OA 后，由 Agent 读取完整材料与审批流水，判断同意、拒绝或评论补充要求，并在执行后核验结果。 |
| 工作来源 | 整理工作区中的新工作记录 | 发现工作区中新建或修改的 Markdown、文本文件后，由 Agent 判断其中是否有值得持续跟进的承诺，并按证据创建或更新项目、TODO 和跟进。 |
| OKR 周报 | 生成并发送每周 OKR 管理周报 | 读取所有管理者的实时 OKR，由 Agent 结合工作证据分析进展、风险、领导力和文化表现，生成周报并发布到管理知识库和 CEO-2 管理群。 |
| AI 听记 | 归档新增的钉钉 AI 听记 | 发现尚未归档且可访问的钉钉 AI 听记后，读取可用的摘要和逐字稿并归档到工作区；权限受限或内容不可读时保留同步状态，待后续检查。 |
| DingTalk 消息补查 | 补查遗漏的钉钉消息和日历更新 | 扩大读取范围，找回常规检查遗漏的单聊、群聊 @ 消息和原地更新的日历邀请；发现后由 Agent 按对应的消息或日程规则处理。 |

“执行任务”下拉菜单同步使用可读动作名称：读取新钉钉消息、读取新日历邀请、读取新微信消息、读取已结束会议、读取待审批 OA、收集工作来源、同步听记到工作区、生成并发送 OKR 周报、补查近期钉钉消息。下拉菜单说明只描述该固定代码实际读取或生成的内容，不出现 reply task、Dispatcher 或 Consumer。

## 数据与代码边界

仓库默认名称和描述由定时任务种子定义，服务命令目录只定义“执行任务”下拉菜单的名称和说明。两者语义保持一致，但任务名称和服务命令名称承担不同用途，不互相动态生成。

服务启动时按 `migration_key` 找到内置任务，并分别判断名称和描述：

- 当前字段仍等于任何一个仓库旧默认值时，升级为新默认值。
- 当前字段不等于仓库旧默认值时，视为用户编辑，原样保留。
- 名称和描述独立判断；用户只改过其中一个字段时，只保留那个字段。
- 已删除任务不恢复，也不修改。
- 不新增数据库字段，不重写历史运行快照。

## 页面行为

任务列表继续保持现有结构：名称、运行状态、业务描述、自然语言计划、下次运行、最近状态。只替换不清晰的名称和描述，不增加新的卡片字段，也不改变布局。

任务详情默认只读，并提供明确的“编辑任务”入口；进入编辑状态后显示“保存更改”和“取消编辑”。用户可以修改名称、描述、Cron、时区、执行任务和 Consumer Prompt。服务命令的技术标识不作为默认可见文案。

Prompt 中通过 `$skill-name` 引用 Skill，系统据此确定性保存引用。任务详情和编辑器中的 Skill 标签支持悬停或键盘聚焦预览本次执行锁定的正文：Managed Skill 读取精确 revision，Operation Skill 校验当前名称与摘要哈希；页面不预加载全部 Skill 正文。

## 错误与兼容行为

- 无法识别为仓库旧默认文案的任务不自动修改。
- 用户自建任务不参与内置文案升级。
- 旧运行记录继续显示运行当时保存的名称和描述，保证历史证据不被改写。
- 文案升级不改变版本冲突、启停、手动运行和删除语义。

## 测试与验收

1. 先增加会失败的种子测试，验证九个新名称和新描述。
2. 增加升级测试：旧默认文案会升级；用户自定义名称和描述分别保留；已删除任务不变。
3. 增加服务命令目录测试，确认下拉菜单名称清楚且默认说明不含内部实现词。
4. 更新前端测试，确认列表和编辑器展示新文案，运行记录仍只在技术详情中显示命令标识。
5. 运行 Python 聚焦测试、前端页面测试、前端构建和全量 Python 测试。
6. 重启 `com.ceo-agent-service.main` 后回读数据库和浏览器页面，确认九个内置任务显示新文案、日历邀请任务可见、服务健康、队列可恢复且没有新增失败或卡住任务。

## 非目标

- 不修改定时任务整体信息架构、配色或响应式布局。
- 不改变除日历邀请拆分之外的 Trigger、Agent、Skill、Runtime 或队列架构。
- 不批量改写用户自建任务。
