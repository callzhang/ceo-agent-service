# History 失败可处理状态设计

## 目标

所有需要管理者处理的 History 卡片和详情页必须让管理者直接看懂为什么需要处理、是否产生外部副作用，以及当前可选处理方式。审批、消息、日程、文档、待办和会议只共享这个状态呈现，不共享业务判断。

## 展示

服务根据持久化状态判断某项是否需要管理者处理。需要处理时，History item 内显示一张状态卡：业务状态、需要处理的理由、是否产生外部副作用、重试次数和最近失败时间，以及可选操作。详情页展示相同内容及完整失败历史。不需要处理的失败只展示状态和技术详情入口，不展示操作按钮。

## 可选操作

- 系统依赖已恢复但任务未完成：重试当前任务、暂不处理、人工处理、查看技术详情。
- 业务材料不足且人工可补充判断：要求相关人员补充、暂不处理、人工处理、查看技术详情。
- 已确认外部动作但需要管理者确认后续：确认完成、人工处理、查看技术详情。
- 已确认外部动作且无管理者待办：仅查看处理结果和技术详情，不提供重放操作。

“重试当前任务”复用既有任务和执行代次，不创建新的业务任务或重复外部动作。所有原因和动作根据持久化任务状态、执行回执和错误代码生成；不从用户文本猜测原因。

卡片标题仍可点击进入详情；按钮只对当前需要管理者处理的项目展示。原因、
外部副作用和选项在卡片正文中固定出现，不依赖鼠标悬停或折叠区域。

## 自动重试计划

仅在确认尚未产生外部副作用、错误可重试且任务未达到最大次数时，History item
展示指数退避计划。延迟随连续失败次数增长，并受现有最大延迟限制；下一次时间必须由
任务持久化的 `available_at` 读取，不能在页面临时猜算。达到最大次数、错误不可重试、
副作用未知或恢复条件需要管理者判断时，自动重试停止，item 转为“需要你处理”并显示
相应选项。

## 验收

1. 每个需要管理者处理的 History item 无需进入详情即可显示理由和可选操作。
2. `codex_provider_unavailable` 在服务恢复后显示“服务曾不可用，任务尚未完成”，并提供重试、暂不处理、人工处理和技术详情。
3. DWS 读取/解析失败不出现“要求申请人补充”。
4. 操作后保留审计记录，并通过实际 8765 页面验证。
5. 自动恢复项显示当前尝试次数、下一次自动重试时间和升级条件；页面刷新不会改变计划。
