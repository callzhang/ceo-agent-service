# Settings Skills 功能机制管理设计

## 目标

在 Settings 中增加 Skills 页面，用于管理本服务内置的业务功能机制，并提供项目 skill 文件的预览与编辑能力。

本设计的关键语义是：开关控制“功能机制是否继续为新输入创建任务”，而不是简单控制 Agent 是否可以读取某个 `SKILL.md`。一个功能可以关联多个顶层 skills；不存在 skill 下的子 skill。

## 范围与非目标

### 范围

- Settings 侧栏新增 `Skills` 页面，沿用现有 Settings 的侧栏 + 内容卡片布局。
- 页面展示功能机制、启用状态、功能说明及其关联 skills。
- 每个项目内置 skill 都可以进入详情，查看真实文件内容或编辑并保存到对应的 `SKILL.md`。
- 每个功能机制有一个独立开关。
- 关闭功能只影响新任务路由；已运行和已排队任务保持原状。
- 功能与 skills 的关系使用声明式清单维护，允许一个功能关联多个 skills，也允许一个 skill 被多个功能复用。

### 非目标

- 不扫描或编辑 `~/.agents/skills`、`~/.codex/skills`、`~/.codex/plugins` 中的用户、系统或插件 skills。
- 不在本页面管理外部 operation skills（例如由 DingTalk/Lark 提供的读取能力）；如某个功能依赖外部能力，只以只读依赖信息展示。
- 不对已有任务做迁移、取消、重试或状态重写。
- 不在本功能中引入新的审核、授权或外部发送策略。

## 核心模型

### Skill

Skill 由项目 `skills/*/SKILL.md` 提供。目录名必须与 frontmatter 中的 `name` 一致，并保留现有 `metadata.managed_by: ceo-agent-service` 校验。

页面对每个有效 skill 展示：

- 名称和描述；
- 项目文件路径；
- 最近修改时间；
- 被哪些功能机制引用；
- 预览和编辑入口。

### 功能机制

功能机制是可被新输入触发的一条业务处理能力。每个机制包含：

- 稳定的 `feature_id`；
- 显示名称和说明；
- 一个或多个项目 skill 名称；
- 新任务入口标识；
- 默认启用状态。

功能与 skill 的关系保存在提交到仓库的声明式清单 `data/config/skill-features.json` 中，不写死在 React 页面或路由分支里。清单中的每个 skill 名称必须能解析到项目 `skills/` 下的有效文件；外部 operation skill 只能作为只读依赖描述，不能成为本页面的编辑目标。

### 启用状态

启用状态保存在运行时状态文件 `data/config/skill-state.json`，与 skill 正文和功能清单分离。首次没有状态记录时使用清单的默认值（保持现有功能行为）。状态文件采用原子写入，服务重启后继续生效。

## 运行时语义与数据流

1. 服务启动或处理新输入时加载功能清单和状态文件。
2. 每个功能的现有新任务入口在创建任务前检查自己的 `feature_id`。
3. 功能开启时，沿现有路由继续执行并创建新任务。
4. 功能关闭时，该入口直接结束本次功能路由，不创建新任务；不得把已存在的任务改成其他状态。
5. 已运行和已排队任务不重新读取开关，也不被取消或暂停。
6. 一个 skill 被多个功能共用时，关闭其中一个功能只阻止该功能的新任务，不能从全局 skill catalog 删除该 skill，也不能影响其他开启的功能。
7. 若功能清单引用的项目 skill 缺失或校验失败，该功能标记为“配置不完整”，不创建该功能的新任务；其他功能继续工作。

运行时仍保留当前安装副本兼容性：项目 `skills/` 是 Settings 的编辑源；保存成功后通过现有 service-managed 安装/同步事务更新运行时副本。只有项目源文件写入和运行时同步都成功，接口才返回成功。

## 页面设计

### Settings 导航

在现有 Settings 左侧导航新增 `Skills` 项，位置靠近 `Agent Runtime`/`Prompts` 等运行配置项。页面采用现有 A 方案：左侧导航，右侧卡片内容。

### 功能列表

右侧顶部显示启用数量和说明：“管理哪些业务功能可以为新输入创建任务”。每个功能卡片包含：

- 功能名称、业务说明；
- `ON/OFF` 开关及当前状态；
- 关联 skills 的名称标签；
- “查看关联 skills”入口。

关闭后在卡片内显示明确提示：新的该类输入不会创建任务，已经运行或排队的任务不受影响。

页面必须同时提供“全部 skills”视图或展开区域，确保项目 `skills/` 下的每个有效 skill 都能被找到，即使它当前尚未关联功能。未关联 skill 仍可预览/编辑，但没有功能开关。

### 关联 skills 与详情

点击功能卡片的关联区域进入关联列表。每个 skill 行展示描述、路径和“预览 / 编辑”按钮。若 skill 被多个功能引用，详情页显示引用数量及功能名称，并在编辑区提示修改会影响这些功能。

### 预览与编辑

- 预览显示真实 `SKILL.md` 正文，不生成脱离源文件的副本。
- 编辑使用多行编辑器，显示相对项目路径和当前文件版本摘要。
- 保存按钮明确写为“保存到 SKILL.md”。
- 保存成功后显示文件已保存、运行时副本已同步；保存失败保留编辑草稿并给出具体失败阶段。
- 并发编辑时使用读取时的 SHA 作为 `expected_sha256`；文件已经变化则拒绝覆盖，提示重新加载。

## API 边界

提供独立于通用 Settings payload 的窄接口：

- `GET /api/console/settings/skills`：返回功能清单、启用状态、全部项目 skills 及配置完整性。
- `POST /api/console/settings/skills/{feature_id}/toggle`：只更新功能启用状态并返回最新状态。
- `GET /api/console/settings/skills/{skill_name}`：返回 skill 元数据、正文、SHA 和引用功能。
- `PUT /api/console/settings/skills/{skill_name}`：接收正文和 `expected_sha256`，校验后原子写回项目文件并同步运行时副本。

所有名称使用后端解析后的清单 ID，不接受任意文件路径。路径必须落在项目 `skills/` 目录内；目录穿越、符号链接逃逸、错误 frontmatter、目录名与 `name` 不一致均返回可读错误。

## 一致性、恢复与错误处理

- 功能状态写入失败：保持旧状态，返回错误，页面不更新为新状态。
- skill 文件校验失败：不写入文件，返回字段级错误。
- 项目源写入或运行时同步任一步失败：保留原文件、临时恢复数据和错误阶段；不返回“已生效”。
- SHA 冲突：返回冲突状态和当前 SHA，要求页面重新加载后再编辑。
- 清单引用缺失 skill：功能显示配置不完整并阻止该功能的新任务，不阻塞其他功能或整个 Settings 页面。
- 页面加载失败：保留现有 Settings 的错误卡片和重试行为；单个 skill 的错误不应使其他功能列表不可见。

## 测试与验收

### 后端和运行时

- 清单解析、重复 ID、缺失 skill、frontmatter 校验和默认启用值。
- 一个功能关联多个 skills、一个 skill 被多个功能复用。
- 状态文件持久化、原子写入和服务重启后的读取。
- 开启/关闭功能对新任务创建的差异；已有运行/排队任务不变。
- 缺失依赖只阻止对应功能；共享 skill 的其他功能仍可路由。
- 文件路径边界、符号链接、SHA 冲突、原子写入和同步失败恢复。

### API 和前端

- 功能列表、全部 skills、切换接口、详情接口和编辑接口的成功/失败响应。
- Settings 导航高亮、功能卡片、关联 skills 展开、预览/编辑切换。
- 开关成功、失败和配置不完整状态的可见反馈。
- 保存成功、SHA 冲突、校验失败和同步失败提示；编辑草稿在失败后保留。

### 发布验收

完成测试后重启 `com.ceo-agent-service.main`，确认新进程读取持久化的功能状态；验证一个开启功能可以为新输入进入现有路由，关闭同一功能后新输入不创建任务；最后检查没有新增 `failed` 或卡住的任务。

## 实施顺序

1. 建立功能清单、状态存储和项目 skill 发现/校验服务。
2. 接入新任务入口的功能开关检查，保持旧任务行为不变。
3. 增加 Console API 和 Settings Skills 页面。
4. 增加预览、编辑、SHA 冲突和运行时同步。
5. 补齐单元、API、前端和路由回归测试，执行发布验收。
