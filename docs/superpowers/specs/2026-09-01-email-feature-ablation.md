# Email classifier feature ablation

更新时间：2026-09-01

## 实验目的

在同一批真实邮箱样本和同一时间顺序 holdout 上，检查分类质量是否主要受
发件人身份特征、主题/正文选择或 Logistic 正则强度影响。

## 数据边界

- 复用随机种子 `20260906` 和 `20260907` 的两批样本，合并为 `80` 个唯一 UID；
- 为防止邮箱新增 UID 改变随机抽样结果，本次修正版使用首次抓取时保存的精确 UID 集合；
  样本身份 digest 为 `f5c3d1b283ab96d20468ba40e09c33625153c15bec7d749517e65bff791dd719`；
- 前 `60` 封按 UID 时间顺序训练，后 `20` 封 holdout；
- 标签为本次会话的 `assistant_provisional_annotation`，不是用户确认反馈；
- 生产特征路径只处理标准邮件头和正文文本，附件保持 metadata-only；
- 没有执行邮箱写操作，没有创建任务，没有写入生产数据库。

## 结果

| 特征/参数 | Accuracy | Macro F1（实际 holdout 类别） | 预测 P95 | 最大置信度 |
| --- | ---: | ---: | ---: | ---: |
| 生产全部特征，C=0.10 | 55.00% | 37.82% | 0.22 ms | 0.2180 |
| 生产全部特征，C=0.25 | 55.00% | 37.30% | 0.22 ms | 0.2442 |
| 生产全部特征，C=1.00 | 50.00% | 29.05% | 0.21 ms | 0.3484 |
| 发件域 + 主题 + 正文，C=0.10 | 55.00% | 37.82% | 0.22 ms | 0.2179 |
| 发件域 + 主题 + 正文，C=0.25 | 55.00% | 37.82% | 0.22 ms | 0.2441 |
| 发件域 + 主题 + 正文，C=1.00 | 55.00% | 33.64% | 0.23 ms | 0.3481 |
| 主题 + 正文，C=0.25 | 55.00% | 37.82% | 0.22 ms | 0.2451 |
| 仅主题，C=0.25 | 30.00% | 26.19% | 0.10 ms | 0.2287 |
| 仅正文，C=0.25 | 55.00% | 37.30% | 0.21 ms | 0.2441 |

所有 Logistic 变体在 `0.85` 阈值下覆盖率均为 `0`。实际 holdout 中
`work` support 为 `2`，所有变体的 work recall 都为 `0`；holdout 的
`junk` support 为 `6`，多数变体的 junk recall 也很低。

此前同一文件中记录的 `30%` 结果使用了变化后的 UID 总集合，标签与样本错配，
已由本次精确 UID 重跑结果替换，不再作为有效证据。

## 结论

1. 去掉发件人 hash 或只保留域名、主题和正文，在本次精确样本上与生产全部特征
   基本相当；没有证据表明 sender identity 是唯一瓶颈。当前不因这批 provisional
   数据修改生产特征契约。
2. `C=0.10/0.25` 的标签结果一致，`C=1.00` 的 Macro F1 反而下降；置信度最高
   仍只有 `0.3484`，不能满足现有自动处理阈值。
3. 仅主题的延迟更低但质量明显更差；仅正文与完整特征相近，但差异来自小样本
   holdout，不能视为稳定收益。继续保持 word-unigram TF-IDF + balanced Logistic
   作为 CPU 候选，不为这批 provisional 数据增加复杂特征。
4. 下一步收益点仍是用户确认反馈和类别覆盖，尤其是 `work`、`subscription`、
   `personal`、`shopping`，而不是继续做参数搜索。active model、自动回复和
   自动退订继续关闭。
