# OA 高风险授权卡：具体动作而非“重跑”

## 问题与目标

Attempt 9733 已知没有 OA 操作、消息发送或 provider 回执。其历史 Consumer
运行因 Codex session writer conflict 失败；随后一条完整的 Consumer 结果把当前
OA 事项投影为 `needs_human`。现有卡片的“授权本审批重跑”允许服务重新分析并可能
同意、拒绝或退回，用户无法知道自己授权的外部效果。

目标是保留真正的高风险逐项授权，同时使人能在不阅读原始运行日志的情况下知道：

1. 当前没有外部动作发生；
2. 当前 Agent 建议的唯一外部动作、对象和可见后果；
3. 自己是在作一次性授权，还是同时提出一条可沉淀为 Skill 的规则反馈；
4. 技术失败不会被重新包装为授权问题。

本设计不改变 OA Skill 的材料、规则、风险和动作门槛，也不改变任何已发生的 OA
动作、消息或历史 run。

## 备选方案

### A. 保留“授权重跑”

优点是实现最小；缺点是授权范围不确定，可能让服务在重跑后选择任何审批动作。
这不满足“2 至 4 个可执行选项”的可预期性要求，也无法区分技术恢复与业务授权。

### B. 具体动作授权（推荐）

Consumer 只有在已经形成一个完整、单一、未执行的动作计划时才能请求授权。卡片显示
该动作的自然语言说明、目标 OA 实例/任务以及通知对象；用户选择“仅本次授权执行此
动作”或“保留当前待办”。选中 Skill 更新时，同一份反馈同时成为规则迭代输入，但不把
一次授权自动推广到未来所有审批。

优点是授权范围可核验、重跑不会扩大动作范围、可以直接绑定同一 session 的新 revision。
缺点是没有确定动作计划的高风险事项不能显示授权按钮，必须按 OA Skill 继续补齐材料、
规则或生成明确方案。

### C. 取消逐项授权，改为全局 Skill 放行

优点是人工介入最少；缺点是把一次高风险 OA 的授权扩大为长期规则，无法安全表达例外、
金额、对象或角色边界。本设计不采用此方案；全局规则只能由用户显式选择 Skill 更新后
另行评估和写入。

## 设计

### 1. 结构化授权计划

`needs_human` 的高风险 OA 结果新增必填 `authorization_plan`。它不是错误字段，至少包含：

- `action_kind`：当前唯一拟执行的业务动作；
- `target`：当前 `process_instance_id`、`task_id` 及必要的回退节点或审批动作身份；
- `summary`：给用户看的中文动作说明；
- `side_effects`：可能发生的 OA 操作和受影响通知；
- `readback`：执行后必须读取的 OA 或消息回执。

计划必须与 `proposal.actions` 一一对应，且只允许一个业务审批动作。若计划为空、含多个
互斥审批动作、目标不匹配当前 Attempt，或只写“重新判断/重跑”，结果契约校验失败并进入
普通反馈/失败路径；不得显示授权按钮。

### 2. 决策质量与技术错误分离

`risk`、`confidence`、`information_completeness`、`rule_coverage` 继续是所有结果的通用字段。
其中 `confidence` 只描述证据和判断的确信程度；“尚无 Derek 对本实例的授权”记录为
`authorization_required` 和 `authorization_plan`，不能把授权缺失写成低置信度的理由。

技术、路由、session、schema、Audit 或重试错误不能形成 `authorization_plan`，也不能单独
使 Attempt 成为 `needs_human`。它们保留在 History 的 `stopped_because`，按正常恢复或
失败规则处理。

高风险 OA 在有完整材料和规则、但 Skill 明确要求本条具体授权时，仍可进入 `needs_human`；
它的理由是“高风险动作尚未取得本次授权”，而不是“系统需要重跑”。

### 3. 页面与反馈语义

页面顶部固定显示：

> 当前没有执行外部动作。Agent 建议仅对当前 OA 事项执行：{summary}。

页面只显示两个互斥且可执行的主选项：

1. `仅本次授权执行：{summary}`；说明会执行哪些外部动作、不会执行哪些动作、以及会读回什么；
2. `保留当前待办，不执行外部动作`。

“同时沉淀为 Skill 规则”是独立复选框，默认关闭；它与一次性授权可同时选择。提交后：

1. 保存用户反馈和授权选择；
2. 若选择 Skill 更新，形成受审计的 Skill 更新输入；
3. 对同一 session 创建新 revision，而不是创建新的 session 或 Attempt；
4. 执行前重新读取当前 OA 状态，确认目标仍为 RUNNING、归属仍正确且计划仍匹配；
5. 执行、保存 provider receipt，并按计划读回；状态收口为成功、明确失败或新的真实规则反馈。

### 4. Attempt 9733 的迁移规则

9733 当前只包含“重新判断并执行”的宽泛描述，且页面证据中没有可供授权的结构化单一动作计划。
它不应继续展示“授权本审批重跑”。迁移后其当前投影应收口为 `failed`，保留历史的 session
writer conflict 和任何已完成 Consumer 记录；只有后续 Agent 在同一 session、新 revision 中
产生符合本设计的具体 `authorization_plan`，才可以重新进入 `needs_human`。

## 验收与测试

1. 一个技术/session 失败且没有授权计划的结果不能生成 `needs_human` 或授权选项。
2. 高风险完整 OA 结果若有一个合法单一 `authorization_plan`，页面显示动作、对象、外部影响、
   readback 和两项明确选项；不出现“重跑”“可能同意、拒绝或退回”等不确定措辞。
3. 多个互斥审批动作、目标不匹配、空计划或泛化重跑计划均被结果契约拒绝。
4. 授权反馈创建同一 session 的新 revision；Skill 更新复选框可与一次性授权同时保存。
5. 重新执行前读取当前 OA 状态；执行后验证 provider receipt 和 OA/消息读回。
6. 9733 的历史仍可查看、没有外部动作被伪称已完成，且没有合法计划时不再显示人工授权卡。

## 非目标

- 不自动同意、拒绝或退回任何现有 OA；
- 不把单次授权升级为全局 Skill 规则；
- 不修改历史 run 或删除审计证据；
- 不为 History 读取增加任何外部 CLI、DingTalk 或 OA 副作用。
