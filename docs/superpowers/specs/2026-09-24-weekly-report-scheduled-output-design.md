## 修法

### 1. 时间

- 定时：每周六 12:00，时区 `America/Los_Angeles`（Derek 说的「本地时间」，即本机当前时区）。
  折合北京时间是周日 03:00。
- 目标周会：运行时刻之后的第一个周一（按北京日期）。周六跑，目标就是后天的周会，不是已经开完的那次。
- 统计窗口不变：上一个周一 00:00 到目标周一 00:00（北京时间），实际截止到运行时刻并在报告里写明
  （契约里的 early run 规则）。

### 2. 找不到文档就建

- 在「{目标年份} 年：管理层周会」文件夹里，按标题 `{年}年{月}日{日}管理层周会` 找目标文档；上期是前一个
  周一的那篇。
- 目标文档不存在：在该文件夹下新建同名空文档，然后照常写入（Derek 2026-09-24）。
- 找到多篇同名的仍是硬错误（不猜是哪篇）。

### 3. 材料收集拆成服务只读命令

新增 `app.cli weekly-report-materials --scheduled-run <触发记录 id>`，登记为服务只读命令（和
`daily-report-facts` 同一张表）。它把确定性的收集一次做完，输出一份 JSON：

| 内容 | 来源 | 说明 |
|---|---|---|
| 窗口 | 触发记录 | 目标周一、起止、截止时刻 |
| 目标 / 上期文档 | 知识库文件夹列表 | 标题、node ID、是否已存在、当前 revision |
| 听记清单 | 本地归档 `~/Documents/memory/AI听记` | 窗口内每份听记的标题、时间、本地文件路径、摘要开头。归档由每天 20:00（北京）的听记同步写入，周日 03:00 运行时周六的听记已在 |
| Derek 的群消息 | `dws chat +search-msg` | 窗口内 Derek 发的消息，原样保存 |

Agent 拿到后直接按路径读本地听记，不再逐条调接口下载，这是省时间的主要来源。CRM、四条业务线报告
（哪篇算报告要判断）、公司 OKR 仍由 Agent 读。建目标文档是写操作，不放在这个命令里，由 Agent 作为
外部动作提出、审核轮执行。
