# Automatic service error repair

New recorded service errors and failed reply Attempts enqueue repair coordination in existing `service_state` in the same transaction as the source failure. The failed-Attempt notification entry also idempotently enqueues its exact source. Business `needs_human` choices do not trigger repair. Historical failures are not mass-enqueued. Original failure/business delivery state is never changed by creating a PR.

The existing Workbench scheduler checks this outbox every ten seconds and runs one repair conversation at a time. The parent and its source association commit atomically. Turns use the normal native Workbench runtime, routing, CLI approval, leases, deployment drain and recovery. No new runtime route or task kind is used. Request IDs include source and turn number, so a crash between turn creation and checkpoint reuses that turn. Explicit stop stays stopped. Missing delivery continues the same conversation up to the shared `MAX_AUTOMATIC_ATTEMPTS` (currently four). A terminal diagnostic can report `no_code_change` or `blocked` with its concrete evidence.

After a terminal turn, the coordinator reads GitHub with `gh pr list --head <stable-branch> --state all`. A real remote PR closes the repair as `pr_created`, including when the Agent created it but its final response was interrupted. A textual claim without that receipt does not close it. PR lookup uses the existing bounded external retries; exhausted lookup errors remain visible as `awaiting_pr` and are rechecked every fifteen minutes without restarting the Agent. PR created means only a reviewable change, not CI green, merged, deployed, or business recovery.

Both `/attempts/{id}` and `/history/errors/{id}` expose persisted repair status, conversation link, remote PR link and unresolved reason. The shared card refreshes queued/running state every five seconds through the read-only `/api/console/repairs/{source}/{id}` API. Reads never launch work.

## Procedure for the repair Agent

1. Read `/Users/derek/.agents/AGENTS.md`, the repository `AGENTS.md`, `docs/architecture.md`, `docs/runtime-mechanism.md` and `docs/agent-claims.md`. The user has authorized autonomous diagnosis, scoped development, tests and PR creation for the exact error. Stop at PR: do not merge, deploy, replay the original message, send business messages, or execute the original approval/action.
2. Read the source identified in the prompt from the existing local detail API. Use the exact database path supplied in the prompt for read-only source queries; do not guess a checkout's `data/` database. The generic error may identify a specific scheduled task, meeting, work item or reply. Follow those exact identities to their task and native evidence.
3. Read the complete actual trajectory: submitted developer/task input, selected schema, tool calls/results, model output and validation/execution error. For an Attempt, `/api/console/history/{id}` supplies `runtime_attempts[].run_id` (Run IDs, not Attempt IDs). `/api/console/settings/prompt-preview?run_id=<run>` reads exact submitted input. The native current database has `runs` and `runtime_attempts`; inspect their declarations before querying. `runtime_attempts.parent_id` points to a Run and its session ID plus transcript bounds identify native evidence. The source's `app/native_trajectory.py` supplies runtime-owned readers. No native input/output copies or credentials belong in a public PR.
4. State expected versus actual and prove the failing mechanism. Distinguish code bugs from expired authentication, missing permissions, dependencies, and a real business rule decision. Do not invent a code fix for an external condition. Reuse an existing fix/PR when it already addresses the exact failure.
5. Fetch `origin/main` in the development repository. Use the exact branch and isolated development worktree supplied in the prompt. If they already exist, continue there; never discard their progress or rewrite another author's commit. Never edit, build, or test in `~/Services/ceo-agent-service`. Claim only the files needed for this repair.
6. Write a narrow regression and run it before implementing. Fix the mechanism permanently, run the relevant tests under the fixed 2 GB/10 minute limits, and update behavior docs. Do not add aliases, permissive parsing, case-specific keyword heuristics or task-level runtime-route branches. No incidental Audit/authorization/safety-policy changes.
7. Inspect the diff, commit only this repair, push the stable branch, and create the PR with `gh`. Include the problem, resulting behavior, red/green test evidence, CI state and remaining gaps. Read the PR back. Release the claim after push. Keep the reviewable worktree; remove only task-owned disposable probes and exports.
8. Return raw JSON exactly: `{"outcome":"pr_created","summary":"PR URL, commit, root cause, test commands/results, remaining gaps"}`. For a proven external/non-code issue return `no_code_change`; for an unresolved blocker return `blocked`, explaining the exact missing condition. Do not end with a plan or an intention to continue. The coordinator finds the PR from the stable branch independently of this final text.
