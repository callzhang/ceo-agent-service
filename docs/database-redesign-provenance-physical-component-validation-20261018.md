# Unselected physical provenance component validation — 2026-10-18

This E1 unit adds a default-off, body-free Signal/provenance declaration and caller-transaction writer. It does not select the new schema in Store, convert or retire `business_source_documents`, read a provider or native source, migrate a real database, or release runtime code. Tasks 2–6 in the physical implementation plan remain separate. The existing selected body writer and reader remain authoritative.

The first exact Signal version stays inline on its Action. On a second distinct Signal for the complete seven-scalar-plus-body identity, one savepoint creates a parent from the first persisted binding, changes that first payload to FK-only without changing its public ID or independent title/context/dedupe/time, and inserts the second owner. A third owner stores only the FK. The incoming optional coordinate does not define version identity: an absent or different valid coordinate reuses the first persisted coordinate. The existing raw insert contract still raises on duplicate dedupe keys; service-level replay remains with the existing TaskSemanticService pre-insert lookup. A failed second insert rolls the savepoint back even if the caller catches the error and commits other work. The function requires an active caller transaction and never commits it.
