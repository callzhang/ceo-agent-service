# OA 审批最新事实读取

钉钉 OA 审批必须按 `dingtalk-misc` 的 `references/oa.md` 执行。服务自有的
`app.cli read-oa-approval-detail` 负责提供审批实例状态、表单、任务和操作记录的
规范化读取。执行同意、拒绝或退回前，必须重新读取这份 canonical 详情并用它确认
流程仍在运行、当前任务仍属于本人；扫描器的列表结果只负责发现待办。

每次运行都以最新一次 canonical OA 读取为事实源，不比较两次读取并制造“读取冲突”。
审批在两次扫描之间发生评论、附件或操作记录变化是正常流程变化，不是系统异常；仍在
运行的当前任务应把新材料作为最新上下文，继续按 OA skill 重新判断。

如果 canonical 读取显示流程已经结束、当前任务已被其他人处理，或者当前待办已经不再
存在，本轮直接 `no_action`（skip），不再执行审批写操作，也不再重试。

只有 canonical 读取本身不可用时，才允许返回不带业务决策选项的 retryable 技术失败；这
不是 OA 业务状态，不能要求 Derek 在“同意/拒绝”之间选择。

History 应显示“审批已由其他处理 / 已完成（跳过本次执行）”或“审批仍待处理，已按
最新材料重新审阅”，而不是暴露“读取冲突”并生成业务决策选项。
