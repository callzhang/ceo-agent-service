# Consumer/Audit OCR tool visibility, 2026-10-20

The selected failure was repeated `dependency_read_unavailable` on scanned OA materials. Read-only inspection of the complete Consumer trajectory for task 405641 found that the attachment reader returned the original page identity and a bounded JPEG OCR payload, but the Agent could not find `ai_services.ocr_document`. From 2026-10-19 through the pre-fix sample, tasks 405641, 405464 and 405439 had 222, 34 and 17 failed Consumer runs with this error code. These counts describe the observed failure pattern, not an OA business outcome.

The service manifest and role approval options already configured AI Services. The final Codex role command in `app/wechat/codex_safety.py` nevertheless set `mcp_servers.ai_services.enabled_tools=[]`, overriding tool visibility for both Consumer and Audit. PR [#170](https://github.com/callzhang/ceo-agent-service/pull/170) changes that final list to `['ocr_document']` only. Other AI Services tools remain unavailable; the change does not alter OA decisions, retry policy, Audit gates or external actions. The concurrently merged OCR call guidance in `app/consumer_agent.py` was preserved during integration.

## Follow-up: native MCP namespace visibility, 2026-10-20

A later read of the complete Consumer trajectory for Attempt 15707 found a second, distinct visibility gap. The Consumer received the OCR-required page bytes and had the `ai_services.ocr_document` role-scoped tool setting, but the final role command exposed only `mcp__agent_cli` through Native CodeMode's direct-only MCP namespace setting. As a result, the model could not call the already configured OCR tool and reported it as unavailable. This failure was in the role command's namespace list, not in the service manifest, per-tool approval, or attachment reader.

The fix adds `mcp__ai_services` to the Consumer/Audit direct-only namespace list while retaining `ai_services.enabled_tools=["ocr_document"]`, the existing per-tool approval, and all other sandbox and action boundaries. The regression test asserts both role command builders contain the namespace and the OCR-only tool list. Focused role-boundary, service-config and namespace tests passed (71 tests); Ruff and `git diff --check` passed.

A new positive native CLI OCR call was not verified in this checkout: the local CLI rejected its existing `mcp_servers.agent_cli` configuration with `invalid transport` before starting the probe. This does not change the diagnosis or the regression result, but it means this checkout's verification proves command construction and tests, not a fresh live OCR call. Production deployment and readback remain separate release steps. No production attachment was replayed and no OA action was performed.
