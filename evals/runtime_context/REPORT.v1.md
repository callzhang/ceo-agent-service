# Runtime Context synthetic native comparison, v1

**Result:** This offline comparison does not establish a general business improvement from the candidate instructions. In the original meeting-window scene with the counterpart's timezone unknown, the arm-blind semantic reviewer passed baseline **7/10** and candidate **8/10**. The difference is one native run; both arms usually read the sources and delivered two principal-side candidates with coordination left open. In the known-timezone scene, **both arms failed 0/1** because their Los Angeles–London local-time pairs were one hour wrong after the UK daylight-saving transition. The four bounded negative scenes passed **1/1 per arm**. No action was sent, deployed, or read from a real provider.

The known-timezone failure is real within this fixed tool set. `zoneinfo` independently confirms `2026-10-26T08:00:00-07:00` converts to `2026-10-26T15:00:00+00:00`. The fixture intentionally gives both arms the same three read-only tools and no local computation tool; production Consumer can use native local calculation, so this result tests the prompts and the bounded read-tool path, not the complete deployed tool surface. One known-zone pair is too small to estimate a rate. Core 8/10 versus 7/10 is also too small and is partly dominated by native timeout/format failures. A tool call by itself is not treated as a completed response.
